# Changelog

## Unreleased
- Combined branch: merged `improve/security-quality-gates` (security middleware, plans, schedules, runtime events feed, performance API, orchestrator, Alembic baseline, per-IP live-session cap and session audio budget, Android live voice and pairing) into current `main` (cinematic web command centre, cinematic terminal, live-voice reconnect/approval flow). Conflict resolution kept the newer approval fail-closed behaviour and added the confirmation preview path; the per-client-IP live voice cap now runs alongside the global session cap. 190 tests pass; `ruff check .` is fully clean (previously only the CI gate rules).
- Removed the Docker setup completely (`Dockerfile`, `docker-compose.yml`, `.dockerignore`, `make docker-*` targets and the Compose quick start). JARVIS is local-only: install with `pip install -r requirements.txt` and run with `jarvis serve` or the Windows scripts. The DevOps Dockerfile reviewer and runbooks stay; they are analysis tools, not container infrastructure.
- Web command centre closer to the target concept art: live CPU / RAM / DISK / NET dials in a System resources panel (from the authenticated local performance API, dials turn red above 90%; nothing is shown without a device token), an LLM providers panel with per-provider status lights (server-reported configuration only), a Voice commands panel with tap-to-fill examples, and the stop button is now labelled EMERGENCY STOP.
- Wake word in the browser: an opt-in checkbox listens for "Hey Jarvis" and starts Live Voice. It uses the browser's own speech recognition (Chrome and Edge send audio to their speech service; it is not an offline engine) and is off by default, session-only, and pauses whenever Live Voice is active. The fully local wake word stays in `jarvis start` (openWakeWord).
- `jarvis start` now checks the local voice stack first and prints the exact install command instead of a raw ImportError when sounddevice/webrtcvad/openwakeword are missing.
- Cinematic terminal (`jarvis tui`): command-centre layout with an animated core (ring speeds up while thinking, listening or waiting for approval), top bar, system gauges (CPU, RAM, battery; shown as dashes when not measured), services panel, a "Needs you" panel that shows a pending approval, an AWS DevOps panel (which of aws, terraform, kubectl and docker are on PATH; no credentials or network are touched), tool activity and the conversation. Keys: Enter send, F1 help, F2 input, F3 panels, F4 stop, Ctrl+L clear, Ctrl+Q quit. Narrow or short terminals drop the side panels. Set `NO_COLOR`, `TERM=dumb` or `JARVIS_TUI_SIMPLE=1` for the plain mode without animation. `jarvis tui` now exits with a pointer to `jarvis ask` when not run in an interactive terminal. Approval prompts and the reject-by-default behaviour are unchanged; no new shell permission. Rendered to images and inspected at 150x42, 120x36 and 80x30; also tested on the minimum textual 1.0.0. Plain mode (`NO_COLOR`, `TERM=dumb`, `JARVIS_TUI_SIMPLE=1`) now renders greyscale (Textual clears NO_COLOR at start-up, so it is read first). Emoji glyphs were replaced with plain text (PHONE, VOL, MUTED). Footer and input are no longer clipped at 80x24. Not tried on a real Windows terminal. The reminders list is not in the terminal yet.
- Live voice reconnects after unexpected drops (server restart, network loss): up to 4 tries with 1, 2, 4 and 8 s backoff, with Stop Live Voice as cancel. Auth, origin, configuration and normal closes (including the session-length and idle limits) never retry. The transcript is kept and a marker line says JARVIS does not remember what was said before the drop; no provider-side session resumption is used or claimed. While reconnecting, the microphone is off and the page says so (core title, mode line, readiness gauge and services panel no longer say the session is active).
- Fixed a race: if the connection closed while the browser was still starting the microphone, the microphone could stay on with no session. It is now released immediately. Found with a browser test that kills and restarts the server.
- On screens 860 px wide or less, the voice approval prompt is pinned to the bottom of the viewport so it is visible wherever you scroll. It shows a countdown to the automatic denial, has Approve, Deny and Stop voice buttons, does not trap keyboard focus, and the page keeps bottom padding while it is open. Checked in headless Chrome at 390 px (scrolled to top, middle and bottom; Tab order; timeout removal; no reminder created on timeout). "Gemini Live model" now reads "Session opened (audio not verified)" so an open session is not mistaken for proof the real model works.
- New cinematic command-centre UI: animated AI core with listening/thinking/speaking states and waveform, system overview, connected services, upcoming reminders, approvals panel ("Needs you"), AWS DevOps starters, quick actions and a stop-voice-and-replies button; chat, memory, reminders, workouts, research, coach, nutrition and settings stay available in folded panels. Responsive for desktop, tablet and phone. Every panel shows real state (health check, device token, voice session, live reminders) or says it is not connected; there are no demo metrics, and the readiness gauge counts four real checks only. Checked in headless Chrome at 1600, 1024 and 390 px wide. Real microphone, model and AWS behaviour are untested.
- After pressing Interrupt, audio of the old reply that is still in flight is now dropped until that turn ends (turn_complete or interrupted, or 5 s). Before, late chunks restarted playback and the UI said "speaking" next to "interrupted". Checked in headless Chrome with a fake session; real-model timing is untested.
- Fixed the page script, found by running it in a real headless Chrome: `index.html` called `$("voiceStop").addEventListener`, but no element had that id, so the inline script threw during load and the live voice Stop/Interrupt controls never worked. Added the missing button and a test that every id the scripts look up exists in the page.
- Fixed `/static/live_voice.js` returning 404 (nothing served it), so the live voice client never loaded. Both `app.main` and `app.main_enhanced` now serve it. `app.main_enhanced` (used by the Dockerfile and `run_enhanced.py`) did not include the live voice router at all; it does now.
- Removed a stray literal `\n` shown on the page. The approval prompt now sits under the live voice status line.
- Live voice can ask to create a reminder (`create_reminder`). The server holds the call and sends an `approval_request`; the browser shows Approve/Deny. Only an exact `approve: true` for the matching request id runs it. Deny, a wrong id, a 60 s timeout (`JARVIS_LIVE_APPROVAL_TIMEOUT_SECONDS`), a disconnect, or bad arguments all leave data unchanged. One approval can wait at a time. Tested with a fake session and the client source; not run against the real Live API or a real browser.
- Browser playback queue is capped at 20 s ahead so audio cannot build up lag on a slow device.
- Live voice can now call three read-only tools (current time, open reminders, saved memories). Calls are run server-side, restricted to an allow-list, and anything else is refused. Voice cannot add or change reminders, memories, files or devices. The tool-call wiring was written against the installed google-genai types and tested with a fake session; it has not been run against the real Live API.
- Live voice session guardrails: maximum session length (default 900 s), idle timeout (120 s, pings do not count), per-minute audio volume cap (1.5x real time) and a concurrent-session cap (2). Override with `JARVIS_LIVE_MAX_SESSION_SECONDS`, `JARVIS_LIVE_IDLE_TIMEOUT_SECONDS`, `JARVIS_LIVE_MAX_AUDIO_BYTES_PER_MINUTE`, `JARVIS_LIVE_MAX_CONCURRENT_SESSIONS`.
- Added WebSocket flow tests for live voice against a fake Gemini client (ticket rejection, event forwarding, bad frames, rate limit, idle timeout, session cap). These do not prove behaviour with the real Live API or a microphone.
- Fixed `jarvis_daemon.py` and `run_enhanced.py`, which had escaped triple quotes and failed with SyntaxError.
- Tools that need approval now fail closed: with no confirmation callback they do not run. CLI chat now asks on the terminal before running them.
- Shell classifier no longer treats chained, piped, redirected or substituted commands as safe.
- CI now compiles every Python file and lints for syntax errors and undefined names. (The earlier lint-job claim in this file was not backed by the workflow.)
- Raised dependency floors to versions with no known advisories at the time of the audit: cryptography>=50.0, pillow>=13.0, pyopenssl>=26.4, pytest>=9.0.3, pytest-asyncio>=1.3.
- Added AWS DevOps tools: offline reviewers for Terraform, Dockerfiles, GitHub Actions/Jenkinsfiles and IAM policies, troubleshooting runbooks (ECS, EKS, Terraform locks, Jenkins, ALB, IAM), `aws_read` (read-only AWS CLI) and `aws_change` (always asks first). Not tested against a real AWS account.
- Verified a clean-room build from `requirements-dev.txt` on Python 3.13: full test suite passes (135 tests) and `pip check` reports no broken requirements.
- Fixed Ruff failures in `jarvis/core/agent/voice_tools.py` (two unused `result` assignments and import ordering); `ruff check .` is clean again.
- Added `ruff` and `mypy` to `requirements-dev.txt` so the documented lint commands work in a fresh development environment.
- Hardened containers: added `.dockerignore`, run the image as an unprivileged user, publish the Compose port on `127.0.0.1` only, drop Linux capabilities, and mount only `data/` instead of the whole `app/` tree.
- Canonicalised the backend entry point on `app.main_enhanced:app` in the development docs; `app.main` remains a documented minimal compatibility app used by tests.
- Applied the shared `/api/` sliding-window rate limiter to the canonical enhanced backend, which previously only had per-route slowapi limits, and ordered middleware so security headers wrap 413/429 responses.
- Restored coaching response parity in the enhanced backend: workout and nutrition now return the conservative prompts, `disclaimer` text, and the `suggestions` key the browser UI reads.
- Added an idempotent Alembic baseline migration (`0001_initial`) covering all SQLite tables so `alembic upgrade head` works for fresh and existing local databases.
- Updated the registered tool count in the docs to 137.
- Fixed `scripts/setup-and-validate.ps1` failing to parse in Windows PowerShell 5.1: a UTF-8 em dash in a BOM-less file was decoded as a smart quote and terminated a string early. The script is now ASCII-only, so it parses and runs under stock Windows PowerShell.
- Rewrote `README_ENHANCED.md`, which contained control characters, deprecated `docker-compose` commands and claims for features that do not exist (snooze, memory tags, "production-grade"). It now lists only implemented endpoints and repeats the local-prototype status.
- Added `types-python-dateutil` for mypy, documented the pre-existing mypy baseline, and split `make lint` (Ruff, gating) from `make typecheck` (informational). `make migrate` now creates a manual revision because the hand-written SQLite schema has no SQLAlchemy metadata to autogenerate from.
- Added opt-in dashboard CPU/RAM/disk threshold crossing alerts with locally saved thresholds; desktop notifications require a separate user permission click, and checks run only while the dashboard is open.
- Added a 1 MiB `/api/` request-body limit to both HTTP apps, including bodies sent without `Content-Length`; oversized requests receive a secure 413 response.
- Added default-disabled SQLite interval schedules for five read-only system metrics, with explicit enable/disable/delete controls, best-effort cancellation, bounded status history, and browser management. Scheduled outputs are discarded; arbitrary tools cannot be scheduled.
- Added authenticated SQLite-backed user plans with checklist steps, optional linked due reminders through the existing notification workers, progress/cancellation/deletion controls, bounded status history, browser UI, and personal-data export. Cancelling/completing disables a pending reminder; deleting a plan removes it. Plans do not execute tools; notification delivery remains best-effort.
- Added an authenticated `/api/runtime/events` feed and dashboard timeline for provider request/turn durations and tool lifecycle status. Up to 200 allow-listed summaries persist in SQLite; if persistence is unavailable, the feed falls back to its in-memory ring. This bounded operational history is not a security audit log.
- Added aggregate network byte counters to the authenticated performance API and live dashboard send/receive rates computed from adjacent samples; unavailable OS counters are shown as unavailable.
- Added a shared dependency-aware tool task orchestrator with bounded parallel execution for read-only AI tool batches, serialized state-changing actions, lifecycle events, cancellation, and opt-in transient retries limited to read-only tasks. User-authored plans, durable task state, schedules, and event triggers remain pending; persisted lifecycle history is operational telemetry, not a security audit log.
- Capped Live Voice at two concurrent provider sessions per client IP per process; excess connections are rejected with a specific client status. Provider-account usage budgets and distributed limits remain outstanding.
- Added at most two delayed browser Live Voice reconnect attempts for transient transport/server disconnects, using fresh one-time tickets and a visible Stop-to-cancel path; authentication and provider configuration failures remain explicit errors.
- Added a foreground process and keyboard-automation availability check before desktop text entry; unverified focus now fails without typing.
- Added browser and native Android full-duplex Live Voice code with user-visible start/interrupt/stop controls, bounded audio buffers, short-lived single-use tickets, and server-side session/audio limits. Real provider and device verification remain pending.
- Added Android master-token pairing and confirmed device revocation. The app encrypts the issued device token, backend URL, and device ID with Android Keystore, and does not persist the master token. Device-management endpoints now require the master token; device tokens cannot administer other devices.
- Added recurring daily/weekly/monthly reminders, explicit Android memory controls, and opt-in Android WorkManager reminder notifications. Android delivery remains best-effort and device verification is pending.
- Added configurable per-process IP rate limiting for HTTP API routes and expanded CI to lint Python, parse Windows setup scripts, and build the Android debug APK.
- Required point-of-action confirmation with bounded item/byte and destination previews for file mutations; file changes cannot use session-wide or global auto-approval. Delete fails closed when Recycle Bin support is unavailable, and directory transfers into themselves are rejected.
- Added regression tests for API rate limiting, live-voice bounds and ticket checks, WebSocket auth/provider-timeout handling, recurring reminders, per-device token issue/authentication/revocation, and file-mutation confirmation/preview/fail-safe behavior.
- Updated setup, security, feature, deployment, and verification documentation to distinguish implemented code from unverified CI, provider, and device requirements.
- Reworked the browser dashboard into a voice-first JARVIS command centre with a responsive layout, animated assistant orb, visible listening/thinking/speaking/ready states, and explicit voice controls.
- Added transcript-first capture: speech recognition displays interim/final text for review and does not automatically submit a dictated phrase.
- Added voice cancellation and stop-speaking controls, plus reduced-motion accessibility support.
- Added the real-time voice acceptance checklist. Live Voice paths now exist in code, but actual provider access, browser hardware behavior, Android build, and physical-device tests remain pending.
- Fixed CI dependency mismatch: install the project with development extras so pytest-cov is available for the configured coverage flags.
- Added a Python lint job and regression test coverage for API security headers.
- Added an evidence-based release verification checklist.
